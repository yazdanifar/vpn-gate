### Changed
- Faster CI. Packaging jobs (`msi`, `deb`, `android-engine`) no longer wait for the test jobs. The macOS `.pkg` is built in the `test` job, so the separate `package` job that rebuilt everything is gone. `build-pkg.sh` now runs `build.sh all` once instead of twice. Rust jobs use `Swatinem/rust-cache`, which saves caches only from pushes to `main`/`cross-platform` so PRs restore from their base branch; before, every PR saved about 4 GB of its own caches. The Gradle cache is saved from the same pushes (its default saved only on `main`). A new push to a PR cancels its running suite. Every job has a timeout. Docs-only changes skip CI.
### Fixed
- The .pkg no longer treats the app bundle as relocatable (the installer could update a stray copy instead of installing into `/Applications`), and the daemon creates its data directory before recording undo state, so `--connect` on a fresh Windows machine can be cleaned up after a crash.
- GTK app (found by the U33 tests): the main window no longer deadlocks when the server list arrives (the table's cells read the model while it was locked), the connection settings window shows its empty state, and a refresh no longer resets text typed into the search box.
- CI warnings. Actions moved to versions that run on Node 24 (`checkout@v7`, `upload-artifact@v7`, `download-artifact@v8`, `setup-java@v6`, `setup-dotnet@v6`, `setup-gradle@v5`). The toolchain step uses `rustup toolchain install` instead of rustup's deprecated auto-install. The emulator runs with `-no-metrics`, before its metrics warning becomes a blocking prompt. `ANDROID_NDK_ROOT` now matches `ANDROID_NDK_HOME` for cargo-ndk. The cargo-deb asset paths use `target/release/` (`build-deb.sh` copies the daemon next to the GTK app). The workflows pass shellcheck.
- Release workflow hardening (from code review): the publish job refuses a release APK signed with the debug key (`apksigner` output is checked); the CI keystore is decoded into `$RUNNER_TEMP` instead of the checkout, and `*.jks`/`*.keystore` are git-ignored; release artifacts are downloaded by exact name with a flat layout; releases of the same ref run one at a time; `release.yml` has a `workflow_dispatch` dry run that skips the tag check and publishing.
- `HelperClient` is marked `@unchecked Sendable` (its state is lock-guarded), which removes the Swift concurrency warning printed on every app build.

## [2.0.0] - 2026-10-27
The engine and the privileged daemon are now Rust; the macOS app is a thin Swift client that talks to the daemon over IPC v9.
The macOS behaviour is unchanged (verified by `scripts/e2e-tunnel.sh`: traffic, DNS, IPv6 block, SIGINT/SIGTERM/kill -9 cleanup).
### Removed
- `Sources/VPNGateCore` and `Sources/vpngate-helper` (the Swift engine and daemon) and the Swift tests the Rust tests replace
  (`Tests/Unit`, `Behaviour`, `Fuzz`, `Live`, `Golden`), `scripts/gen-golden.sh` and `scripts/coverage.sh`. The golden vectors in
  `Tests/Fixtures/golden` stay as fixed reference data. `Package.swift` now has the app target only.
### Changed
- `scripts/test.sh` runs the app tests only; engine tests are `cargo test --workspace`, coverage is `scripts/coverage-rs.sh`.
- `scripts/build.sh` fails with a clear message when a Rust target is missing instead of hiding the rustup error.
### Fixed
- Rust daemon: the tun reader thread panicked ("no reactor running") on the first outgoing packet, so a connected tunnel carried no traffic. Packets are now handed to the engine inside the Tokio runtime.

- U15a.2: `vpngate-daemon/tests/tunnel_hermetic.rs` drives the real macOS utun, routes and net config through the real `Session` against an in-process fake relay (only 192.0.2.0/24 is routed, no DNS or default-route change; needs root, `#[ignore]`); the macOS CI leg runs it with sudo. New `e2e.yml` workflow (weekly/manual, non-gating) runs `scripts/e2e-tunnel.sh` against a probed real relay on a runner.
- U15a: Rust property tests (`proptest`, port of the Swift fuzz suite) for pack, data phase, packet parsers, server list,
  validation and the bridge; ignored live-relay tests (`cargo test -p vpngate-daemon --test live -- --ignored`);
  `scripts/coverage-rs.sh` (cargo-llvm-cov, same thresholds as the Swift script) and a `coverage` CI job. `live.yml` now runs
  the Rust live tests and `gen-watermark.sh` emits `crates/vpngate-net/src/watermark.rs`.
- Golden vectors (`Tests/Fixtures/golden/*.json`, `scripts/gen-golden.sh`): Swift-exported input/output pairs for the pure
